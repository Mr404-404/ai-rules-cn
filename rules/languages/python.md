# Python 编码规范

## 基本风格

- 遵循 PEP 8，行宽 100；优先使用 ruff 做格式化和 lint，配置以项目 `pyproject.toml` 为准
- 所有公开函数、方法必须带完整类型注解（参数与返回值）；`main` 脚本内部的临时函数可放宽
- 使用 `pathlib.Path` 处理路径，不使用 `os.path` 拼接字符串
- 字符串格式化统一使用 f-string，不使用 `%` 或 `.format()`
- 优先使用 dataclass / pydantic 表达结构化数据，避免到处传 dict

## 结构与依赖

- 新增第三方依赖前，先确认标准库或项目已有依赖无法实现，并在提交信息中说明理由
- 导入顺序：标准库、第三方库、本地模块，组间空一行；不使用 `from x import *`
- 单文件超过约 300 行时考虑拆分模块；函数超过约 50 行时考虑拆分职责
- 禁止捕获裸 `except:`；捕获具体异常类型，且不允许静默吞掉异常（至少记录日志）

## 注释与文档

- 注释解释"为什么"，不复述代码"做什么"；显而易见的代码不加注释
- 公开 API 写 docstring，采用 Google 风格；一次性脚本不强制
- 删除代码而不是注释掉；被注释掉的死代码不允许提交

## 测试

- 测试框架使用 pytest，测试文件命名 `test_*.py`，与源码目录结构对应
- 修复 bug 时先写复现该 bug 的失败测试，再修复
