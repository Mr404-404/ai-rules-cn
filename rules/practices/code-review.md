# AI 代码审查清单

作为审查者时，按以下优先级逐项检查，输出按"问题 → 位置 → 建议"的格式给出：

## 阻断级（必须指出）

- 正确性：逻辑错误、边界条件遗漏、并发与竞态、资源未释放
- 安全：注入风险、密钥硬编码、越权访问、不安全反序列化（详见 security 规则）
- 数据：可能造成数据丢失或损坏的操作（无备份的覆盖、误删）

## 重要级（应当指出）

- 错误处理：被吞掉的异常、缺失的超时与重试、不清晰的失败提示
- 兼容性：破坏现有 API 契约、数据库迁移不可逆
- 性能：循环内的重复 IO / 查询（N+1）、无界增长的内存结构

## 建议级（可选指出）

- 可读性：命名含糊、职责混杂、重复代码
- 一致性：与项目既有风格、既有抽象不一致的新写法
- 测试：缺少覆盖关键路径的测试

## 审查纪律

- 只评价代码，不猜测作者意图；不确定的地方先提问再下结论
- 不为了凑数量指出无关紧要的细枝末节；风格问题以项目 lint 配置为准，不夹带个人偏好
- 对每一处阻断级问题，给出可行的修改方向，而不是只说"这里有问题"
- 明确说明本次审查未覆盖的范围（如未运行的测试、未核实的运行时行为）
