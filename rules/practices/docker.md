# Docker 规范

## Dockerfile

- 基础镜像使用具体版本标签（如 `python:3.12-slim`），禁止 `latest`
- 优先选择 slim / alpine 等精简变体；生产镜像使用多阶段构建，只保留运行所需产物
- 层顺序按变更频率排列：先装依赖（利用构建缓存），后拷贝业务代码
- 合并连续的 `RUN` 指令减少层数；清理包管理器缓存
- 容器以非 root 用户运行（`USER` 指令）；必须 root 的场景说明理由
- 提供 `.dockerignore`：排除 `.git`、依赖目录、构建产物、本地配置与密钥文件

## 配置与密钥

- 配置通过环境变量注入；密钥严禁写进镜像（包括构建参数），使用运行时挂载或密钥管理
- 镜像内不保留任何环境专属配置；同一镜像应能部署到所有环境

## 运行

- 日志输出到 stdout / stderr，由容器运行时收集，不在容器内写日志文件
- 长驻进程提供健康检查（`HEALTHCHECK` 或编排层探针）
- 单容器单进程；需要多进程编排时使用 compose / Kubernetes，而非容器内起多个服务
- 数据持久化使用卷（volume），容器文件系统视为临时

## Compose

- 服务、网络、卷命名带项目前缀；端口映射避免与常用端口冲突
- 依赖启动顺序用 `depends_on` + 健康检查条件，而非裸 `sleep`
