# SQL 与数据库规范

## 查询

- 一律使用参数化查询或 ORM，禁止字符串拼接 SQL（安全红线，见 security 规则）
- 明确列出所需字段，不使用 `SELECT *`（小表与原型代码可放宽）
- 列表查询必须带分页或 `LIMIT`；禁止无界结果集直接返回给上层
- 避免在循环中逐条查询（N+1 问题）；用 JOIN、批量 `IN` 或预加载解决

## 写入与变更

- 多步写入必须包在事务中；明确事务边界与失败回滚策略
- `UPDATE` / `DELETE` 必须带 `WHERE`；执行前先用同条件 `SELECT` 确认影响范围
- `DROP` / `TRUNCATE` / 无 `WHERE` 的全表操作：AI 不得直接生成可执行命令，必须显式提示风险并由用户确认
- 表结构变更一律通过 migration 文件管理，不直接在数据库里手改；migration 须考虑可回滚

## 设计

- 表名、字段名使用 snake_case；跟随项目已有命名约定
- 新表必须有主键；常用查询条件字段评估加索引，并说明依据
- 金额用 DECIMAL，禁止 FLOAT；时间统一存 UTC 时间戳或带时区类型
- 大字段（长文本、JSON、BLOB）评估拆表，避免拖慢主表查询
